## 1. 最大の dev 効果が消えた

**T0-B1 h=48 Y2 は dev の family 最大効果だった。** それが 2025年には符号ごと反転した。

| | dev | confirmation |
|---|---:|---:|
| ΔR² | +5.450e-03(27 test 中最大) | −5.154e-04 |
| MDE 比 | 8.1 倍 | — |
| p | 7.13e-04(第2段階 1,402本中0本が到達) | 0.7463 |
| 安定性6条件 | **全通過** | — |
| fold 別 正の割合 | 0.93 | — |
| 正の暦年 | 4/4 | — |
| leave-one-block-out | 全て正 | — |

fold の 93% で正、4暦年すべてで正、LOBO 全正、placebo 1,402本すべてを上回る —
**dev 内で考えうる限りの安定性検査を全て通過した効果が、窓を1つ動かしただけで消えた。**

同じ h=48 の Y3 も反転した(+2.602e-03 → −3.763e-04)。反転した2件はどちらも
**最長 horizon・最小サンプル**(conf n_eff 2,185)である。

これは Phase 3 の教訓(「窓内の安定性は窓外の再現を保証しない」)の再確認であり、
**confirmation 段階を事前登録に入れておいたことが効いた事例**である。
dev だけで判断していたら、最も強い候補を採用していた。

## 2. GO 2件の中身(過大評価しないための注記)

```text
T0-A  h=12 Y2 : ΔR²=+1.626e-03  MDE=+7.103e-04  n_eff=5,877  245日  4 fold
                CI(day-cluster bootstrap 95%) = [−5.364e-04, +3.438e-03]
T0-B1 h=12 Y3 : ΔR²=+1.083e-03  MDE=+2.777e-04  n_eff=8,751  365日  4 fold
                CI(day-cluster bootstrap 95%) = [−7.716e-04, +2.928e-03]
```

両方とも sham S0 を上回り(§17-5)、+1バー遅延でも正を保つ(§17-6)。
事前登録 §17 の GO 条件は全て満たしている。**が、以下は必ず併記する。**

1. **両方とも bootstrap CI が 0 を含む。** placebo に対しては有意(p=0.0033 は
   confirmation の第2段階下限 1/307)だが、日クラスタを考慮したサンプリング不確実性で見ると
   0 と区別できない。両者は別のことを測っている(placebo は「同じ相関構造の列を足したときの
   帰無」、CI は「ΔR² 自体のばらつき」)。**1暦年しかない confirmation 窓では CI が広い。**
2. **confirmation の p は family 補正を通らない。** 27 test の Holm 補正後は
   `27 × 0.0033 = 0.089 > 0.05` で有意にならない。事前登録 §17-4 は
   confirmation の判定を「符号一致と大きさ」で行うと定めており p は判定に使わないので
   GO は成立するが、「confirmation でも有意だった」とは言えない。
3. **dev より効果は小さい**(66.6% と 57.4%)。符号一致と半分以上という条件は
   満たすが、dev の効果量をそのまま将来の期待値と見なしてはいけない。
4. **T0-A の confirmation OOS は 245日**(365日ではない)。2025年に
   `trade_count == 0` のバーが5本あり、`log(0) = -inf` が20日窓を汚染して
   4暦月が §7 のゲートで除外されたため(backlog J7)。dev と同一の凍結変換であり、
   ここだけ手順を変えることはしていない。

## 3. 方向(Y1)は confirmation にすら到達しなかった

dev で Y1 は 9/9 が Holm 非有意だったため、昇格候補が1つも無い。
**Tier 0 で方向情報を検出できるかという問いは、confirmation を開くまでもなく null で閉じた。**

GO 2件はどちらも Y2(実現ボラ)/ Y3(下方到達幅)であり、**方向を含まない**。
現行の backtest 設計(signal → `open[t+1]` 執行)では、この2件から損益は作れない。

## 4. この結果が言っていないこと

1. **「Tier 0 に方向情報が無い」とは言っていない。** 各 cell の MDE を超える方向情報を
   この線形・この変換・この粒度では検出できなかった、である。
2. **「GO = 使える」ではない。** §17 の GO は「Tier 1 の機序検証へ昇格」であって
   戦略実装の許可ではない。CI が 0 を含む以上、効果量の下限は確定していない。
3. **「T0-B1 h=48 に情報が無い」とは言っていない。** 符号反転は
   「dev の推定が過大だった」「2025年のレジームが違う」「n_eff 2,185 では推定が不安定」の
   いずれとも整合する。どれかは今回の設計では区別できない。
4. **Final OOS は依然として未開封。** confirmation は最終評価ではない。

### 6.1 fold 構成の違いが結果を変えることの実例

再現の最初の試行は、§9.2 修正(`b8c5213` / rebase 後 `90e358b`)より前のコードで走っており、
**旧 fold 構成の結果が出た**。記録として残す。

| test | 旧 fold(2025年内で学習・2ブロック) | 正しい fold(dev 開始から学習・4ブロック) |
|---|---|---|
| T0-A h=12 Y2 | ΔR²=+2.138e-03 / p=0.0448 | ΔR²=+1.626e-03 / p=0.0033 |
| T0-B1 h=12 Y2 | ΔR²=−2.863e-04 / p=0.4030 | ΔR²=+1.154e-03 / p=0.0033 |
| T0-B1 h=48 Y2 | ΔR²=+3.895e-04 / p=0.2687 | ΔR²=−5.154e-04 / p=0.7463 |
| T0-A h=1(n_eff) | 35,422 | (h=1 は昇格していないので未実行) |

旧 fold では 27 test 全てが走り(非昇格スキップも未実装だったため)、
**符号すら test によって逆になった**。事前登録 §9.2 が
「dev と confirmation で手順を変えない」ことを要求し、その理由を
「窓が変わったのか手順が変わったのか分からない交絡を作らない」と述べているが、
これはその交絡が実際に結論を反転させうることの実例である。

旧 fold の結果は**手続きが事前登録と違うので confirmation の実行には当たらない**。
破棄した。

## 7. 次の1タスク(推薦)

**GO 2件について Tier 1(aggTrades の event-level 集約)の事前登録を書く。**

理由: §17 の GO は Tier 1 機序検証への昇格であり、次の分岐は事前登録 §20 が
定めるとおり Tier 1 である。ただし今回の GO は CI が 0 を含む弱い GO なので、
Tier 1 の事前登録には **「Tier 0 の GO を再現できなければ Tier 1 も棄却」** という
入れ子の再現条件を含めるべきである。

**やらないこと**: Y2/Y3 の GO を根拠にした戦略実装(方向を含まないので現行の
執行設計では損益にならない)、閾値・horizon の入れ替えによる T0-B1 h=48 の救済
(§17 NO-GO 節)、Final OOS の開封。
