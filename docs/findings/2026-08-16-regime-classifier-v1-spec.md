# レジーム分類器 v1 — 凍結仕様(結果を見る前に確定)

- 凍結日時: 2026-08-16(評価実行前に本ファイルを確定。以降、この版では定義・閾値を変更しない)
- 目的: H6(複合フェード。レンジ・下落月で機能、上昇トレンド月で反転)を
  リアルタイムで ON/OFF するバー時点の分類器。恒久ルール6(オラクル上限・
  定義先凍結・バー時点ローリング量)に従う。
- 全分類器は各時点で過去情報のみを使う(フィッティング無し = walk-forward と等価)。

## 追加する features(features 層)

| 列 | 定義 |
|---|---|
| `drift_20d` | close / close(ts − 20日) − 1。ts 完全一致 join、基準バー欠損なら null |
| `realized_vol_20d` | 窓 [ts−20d, ts)(現在バー含まず)の return_5m 標準偏差。窓内の有効 return_5m が 5,184本(= 20日×288本の90%)未満なら null |

## 分類器の定義(凡庸・標準的な定義を決め打ち。成績での調整はしない)

| ID | ON 条件(フェード許可) | 出典 |
|---|---|---|
| C0 | 常に ON(ベースライン=フィルタ無し) | — |
| C1 | drift_20d ≤ 0 | 「20日リターンの符号」 |
| C2 | drift_20d ≤ +0.08 | +8% は既存の月次レジーム機械ルール(\|月次リターン\|≥8%)から転用 |
| C3 | realized_vol_20d ≥ その日の трailing 中央値 | 「実現ボラの中央値比」 |
| C4 | C1 AND C3 | 事前に許可する唯一の複合 |

- C3 の trailing 中央値: realized_vol_20d を毎日 00:00 UTC にサンプルした日次系列の、
  直前252日分(当日を含まず、最低126日)の中央値を、その日のイベント全てに適用。
- 分類器の入力が null(warmup 等)のバーは **OFF**(トレードしない)。

## 評価方法(凍結)

- イベント集合: H6 凍結条件(return_5m>0 AND volume_ratio_20≥3 AND
  (high−low) ≥ 2×直前20本平均レンジ)かつ fwd_return_1h 非null。全33ヶ月。
- 指標(ショートフェード前提):
  - グロス bps/イベント = −avg(fwd_return_1h)×10⁴、総グロス = −sum(fwd_return_1h)×10⁴
  - イベント数・カバレッジ(対 C0)
  - t 値は実効 N = n/12 で計算
  - コスト後 bps/イベント: taker 往復10bps、maker 往復4bpsを差した値。
    通常Lv1のmaker 2bps/片道を往復2bpsと誤記していたため2026-08-16に訂正。
    実料率は地域・アカウントtierで異なる。
- オラクル(上限): 追試のレジーム表で trend_up(月次リターン ≥ +8%)とラベルされた
  月のイベントを除外した成績。**事後の月ラベルを含む上限値**であり、分類器の評価は
  「オラクル総グロス比の回収率」で行う。
- 補助: trend_up 月(特に 2024-11)のイベントをどれだけ回避できたか(回避率)。
- 集計は (a) 全33ヶ月、(b) OOS のみ(ts < 2026-07-16 17:15 UTC)の両方を併記。
- 報告義務: C1〜C4 の**全て**の結果を選別なしで報告する。この版で定義の追加・変更は
  行わず、変更したくなったら v2 として新たに凍結してから行う。
- 独立監査: 主要値(各分類器の bps/イベントと回収率)を別エージェントが本仕様のみから再計算。

## 結果(2026-08-16 確定・独立監査で全7項目一致)

全期間(H6イベント 4,449件)。グロス = ショートフェードの bps/イベント(−avg(fwd_return_1h))。
t は実効 N = n/12。

| 分類器 | n | カバレッジ | グロス bps/件 | t | オラクル回収率 | trend_up回避 | maker後 |
|---|---|---|---|---|---|---|---|
| C0 フィルタ無し | 4,449 | 100% | +1.43 | +0.39 | 55% | 0% | −2.57 |
| C1 drift≤0 | 1,958 | 44% | +1.87 | +0.33 | 31% | 82% | −2.13 |
| C2 drift≤+8% | 3,206 | 72% | +2.59 | +0.62 | 71% | 56% | −1.41 |
| C3 vol≥252日中央値 | 1,624 | 37% | +3.89 | +0.56 | 54% | 81% | −0.11 |
| C4 C1∧C3 | 1,065 | 24% | +3.86 | +0.43 | 35% | 92% | −0.14 |
| **オラクル(上限)** | 2,869 | 64% | **+4.07** | **+0.95** | 100% | 100% | +0.07 |

- 2024-11(最悪月、105イベント): C1=0件・C4=0件(完全回避)、C2=10件、C3=55件。
- OOSのみ(in-sample窓以前)でも構図は同一(オラクル +3.78bps/件・t=+0.83)。

### 結論

1. **分類器は設計どおり機能した。** 4定義とも C0 よりオラクルに近づき、C2は総グロスの
   71%を回収、C3/C4 は1件あたりグロスをオラクル並みに引き上げ、C1/C4 は 2024-11 を
   完全回避。凡庸な定義で事後ラベル情報の過半は回収できる。
2. **しかしオラクルの器が薄い。** 完璧な事後月ラベルですら +4.07bps/件・t=+0.95 で、
   taker 往復10bps に遠く及ばず、maker 往復4bps 後も +0.07bpsにすぎない。未約定・
   逆選択を入れる前から実質ゼロで、分類器以前にH6のイベント期待値が細すぎる。
3. **判定: H6 は監視リスト入り。** レジーム判定を最良ケースで載せても現行イベント
   定義では戦略にならない。次に方向を追うなら、分類器の改良ではなくイベント定義側の
   再設計(より稀で深い条件)を、新たな探索→凍結→追試サイクルとして回す。

### 監査(独立エージェント、仕様のみから再計算)

全7項目(C0〜C4・オラクル・2024-11件数)が許容誤差内どころかほぼ厳密に一致
(n は全て完全一致、値は±0.01bps以内)。監査が指摘した仕様の曖昧点(v2 で明記すること):

1. C3 の「最低126日」— 「窓内の非null日次サンプル126個以上」(採用した解釈)か
   「履歴126日分以上」か。後者だと n=1714・+4.31bps に変わる。
2. 部分月(2023-11、2026-08)の扱い — 「全33ヶ月」は暦月では34ヶ月分のイベントを含む。
3. H6 の「直前20本平均レンジ」— 現在バー除外・warmup期の部分平均を許容(DuckDB既定)。
4. 中央値の定義 — 補間(DuckDB median の既定)。
